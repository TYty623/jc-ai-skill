# 架构提炼：Java AI 应用的可替换链路

## 分层

```text
HTTP / 流式接口
        │
AI 应用服务 ── 提示词与结构化输出
        ├── RAG：导入 → 解析 → 切分 → 索引 → 检索 → 重排 → 来源回答
        ├── Tool：输入校验 → 授权 → 业务服务 → 审计
        ├── MCP：客户端连接 / Server 工具、资源和提示词
        └── A2A：任务状态、补充信息、异步完成与结果交接
        │
领域服务、数据访问、外部服务
```

控制器不应承担 Agent 编排或领域写操作。它负责协议与鉴权；AI 应用服务负责模型、检索与工具选择；领域服务保持确定性、可测试和可审计。

## 关键设计决策

| 场景 | 建议边界 | 需要记录的证据 |
| --- | --- | --- |
| RAG 问答 | 导入与在线查询分离；切分策略可替换 | 文档版本、chunk、检索分数、来源 |
| 业务 Agent | 工具是窄业务接口，不直接暴露 DAO | 调用者、工具、参数摘要、结果、耗时 |
| MCP 集成 | 将远端连接、可用能力和业务编排解耦 | Server 身份、协议错误、超时、能力清单 |
| 多 Agent | 用显式任务状态而不是隐式聊天上下文 | task ID、状态迁移、输入缺口、最终产物 |
| 流式输出 | 取消、超时、异常和上下文在服务端统一处理 | 会话 ID、首 token 延迟、完成/中断原因 |

## 生产检查

1. 检索结果必须带可验证的来源；没有充分证据时让模型说明不确定性。
2. 对每项工具定义最小输入、允许主体和副作用；模型生成的文本不是授权凭据。
3. 长任务以持久化任务状态恢复，避免只依赖进程内内存。
4. 对模型、向量库、MCP Server 和业务工具分别配置超时、限流与降级。
